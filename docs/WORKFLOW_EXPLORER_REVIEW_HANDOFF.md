# Workflow explorer: review-before-copy agent handoff

This feature is a **local, read-only review step** between OWG's observed workflow map and an agent-neutral text request. It advances [#370 R5/M0](https://github.com/KAVentures/openworkgraph/issues/370), [#326 E](https://github.com/KAVentures/openworkgraph/issues/326) and [#264 stages 1, 5 and 6](https://github.com/KAVentures/openworkgraph/issues/264). It does not run an AI or shadow test, approve a workflow, or create an execution grant.

## Analyst journey

1. Explicitly opt in to OWG recording and capture consenting work through the existing controls. On **Overview**, select the explorer period and **Explore workflows**. OWG reads bounded, existing local evidence; it does not create a new collector.
2. Choose an inferred candidate, inspect separate exact variant lanes, and select a node. **Review selected examples** reads bounded supporting execution references. If a selected variant has no valid references, OWG does not substitute another variant's candidate-wide references.
3. Optionally use **Name or regroup selected examples** to save an explicit human-reviewed classification in the existing versioned grouping ledger. Saving requires its own exact-membership confirmation. A classification is not a verified business case or policy.
4. Click **Review safe agent handoff**. The review displays the selected period, variant, local step labels, omitted steps, bounded reference count, support-inspection status, and reviewed-group revision if present. The user must check the explicit acknowledgement before **Copy reviewed investigation request** becomes available.
5. **Copy non-executing shadow-test plan request** is enabled only for a saved reviewed group with a complete exact displayed variant, valid selected execution references, and a successful current selected-reference evidence inspection covering **every selected reference** (not merely a successful HTTP response or partial overlap), followed by a **local shadow-plan editor** and fresh acknowledgement. The analyst supplies a bounded normal-case expected result, an exception scenario, and an explicit fail/abstain stop rule (each required, at most 320 characters). The editor previews these proposals before copy or local JSON download; changing any criterion clears acknowledgement and disables both actions until the analyst confirms again. The copied request includes the three proposals as **unverified human-supplied data**, never as authority or instructions. It copies a *plan request*, not test results. A model, source system or test runner is never invoked by this UI.

## Portable, non-executing shadow-plan JSON

After the complete selected exact variant has been inspected and the three proposed criteria have been filled, the same **fresh acknowledgement** enables **Download non-executing shadow-plan JSON**. The browser generates and downloads `owg-shadow-validation-plan.json` locally; no API, model, agent, provider, server export ticket or workflow write is involved. The user must inspect the file before choosing to share it. Editing a criterion, selecting another variant or changing the period revokes the old download eligibility.

The portable manifest is **a planning proposal, not a runnable test or grant**. Schema discriminator: `openworkgraph.shadow_validation_plan.v1`; `kind: non_executing_shadow_validation_plan`; `execution_permitted: false`. It includes the exact saved reviewed-group workflow ID/revision, selected UTC window, complete displayed variant number, bounded selected execution IDs, selected-reference inspection limitation, `source_identity_verified: false`, `source_completeness: unknown`, the three human-authored criteria under `human_proposed_untrusted_criteria`, and a `validation` object with `status: not_run` and no observed result. The `safety` section explicitly requires future independent consent, tenant/retention/revision/source checks and separate authorization; it forbids automatic reads, test/agent execution, business writes and claims of validated outcomes. The manifest does **not** include raw evidence bodies, step labels, provider object identities, reviewed-group labels, secrets or executable scripts. User-entered criteria may still contain sensitive data: review the downloaded file before sharing. A recipient must treat all criteria as untrusted text and separately verify permissions.

A saved reviewed classification and a successful bounded inspection do **not** establish business-case identity, a complete provider history, source-authoritative outcome, current permission or the ability to run a test. The JSON file is not automatically imported into any agent runtime and cannot itself run a shadow test. No persistence or automatic external transfer is added.

The copied text deliberately omits raw window titles and displayed step labels; those may be sensitive or adversarial. It contains only bounded execution IDs, selected UTC evidence scope, exact reviewed revision when available, provenance/unknown warnings and read-only instructions. Users must review privacy before pasting it into any external AI. An investigation request may propose **authorized read-only** evidence reads; a shadow-plan request explicitly defers even those reads to a separately authorized future check. The recipient still needs its own current, consent-scoped authorization.

## Safety and stale-state rules

- A new period, candidate, selected node/variant, combined-map selection, or evidence inspection clears the open review and acknowledgement. A late previous evidence response cannot restore it.
- A candidate-wide selection is not silently upgraded into an exact variant. Clipped lanes are not represented as complete; missing refs remain missing. A saved grouping is a human classification, not authorization.
- Shadow-plan prompts explicitly request normal/exception examples, expected outputs, pass/fail/abstain criteria, current source-readback checks and rollback requirements **without tool invocation, execution or business writes**. Neither copied request establishes that any test ran or passed.
- No REST/MCP schema, capture, consent, tenant boundary, retention, canonical evidence, source identity, export ticket or business operation changes. No new server endpoint or remote destination.
- The shadow-plan editor is ephemeral: no server save, local storage, implicit export, model call, test execution, or automatic clipboard action. The explicit JSON download is local only. Plan fields may themselves contain sensitive content, so the user must inspect them before explicit copy and external paste. Source/event text and user-supplied criteria are untrusted data, never executable instructions or authorization.\n- Copy can fail if clipboard permission is unavailable; the UI reports failure rather than success. No hidden upload or auto-execution exists.

## Acceptance and limitations

`tests/browser/explorer_accessibility.cjs` exercises the actual dashboard with a synthetic local evidence server and Chromium: keyboard-only candidate/node selection, WCAG 2.1 A/AA axe checks, review acknowledgement, unlinked-variant non-attribution, disabled shadow planning without current inspection or with mismatched returned refs, an explicitly reviewed and inspected synthetic group, exact revision pin, required normal/exception/stop criteria, explicit portable JSON download and parsed schema/identity/safety assertions, stale acknowledgement after editing, period invalidation, mobile width and no workflow writes. The synthetic inspected group uses a deliberately stubbed bounded response to test the UI state transition; it is **not** a real provider check.

Native exact-head CI, actual-browser/WCAG, OS, scale, packaging and release checks must pass before merging. This milestone does **not** complete the full evidence → reviewed design → idea → sandbox project → report lineage, execute a shadow validation, establish provider authority, meet real-customer UX acceptance, or demonstrate competitor parity/ROI. Those remain separate gates in #370/#326.
