# Observed process review signals and automation scenarios

This is an additive improvement-review layer over the existing opt-in CSV
process mining preview. It does not read the OWG recorder or any remote
business system, does not change source data, and does not create an agent.

## What can be measured

For each explicit CSV case, OWG sorts its recorded events by timestamp, then
computes adjacent transitions. The process report now also includes:

- the median and maximum *elapsed event-to-event gap* for each transition,
  together with counts of cases and transitions;
- review signals for the largest observed gaps;
- repeat signals for activity labels appearing more than once per case.

These are prompts for investigation. A 40-minute gap might represent waiting,
idle time, missing events, normal work in another system, or a timestamp issue.
A repeat might be legitimate multi-step review rather than rework. Neither
is verified operational waste or an automatable opportunity. No labor costs
are inferred from these event timestamps.

## Opt-in scenario calculator

After analyzing an event log in the Evidence tab, users can enter all financial
assumptions independently: cases per month, estimated minutes saved per eligible
case, eligible percentage, loaded labor cost per hour, monthly running costs,
one-time implementation cost, and the chosen currency (SEK/USD/EUR/GBP).

The calculation is deliberately simple:

- eligible cases = monthly cases × eligible fraction
- proposed hours saved = eligible cases × user-entered minutes / 60
- gross monthly labor value = proposed hours × user-entered hourly cost
- net monthly modeled value = gross labor value − running costs
- simple payback = implementation cost / positive net monthly value; otherwise
  no positive modeled payback is asserted

No currency conversion is performed. Inputs are mandatory except costs that
the user explicitly sets to zero. An explicit checked acknowledgement is
required to export the scenario JSON. The saved file contains only user-entered
assumptions, aggregate evidence counts, calculated numbers, and non-approval
markers. It has no native customer/case identifiers.

This is **not a financial forecast, approval, guaranteed savings, authorization
to automate, or measured time savings**. It omits compliance, error rates,
quality, employee ramp-up, capacity and other implementation risks.

## Boundaries and next steps

No DB migration, persistence, AI/cloud call or additional capture permission.
No autogenerated policy, source-system writes, or customer contact. Actual
source-status verification, baselined labor samples, and real-life A/B ROI
trials remain required before confident automation recommendations.

Integration note: this review panel coexists with the human-reviewed AS-IS/TO-BE designer and does not change its process policy or execution boundaries.

## Implementation alternatives

Below the single scenario, **Compare implementation alternatives** puts five
ways of handling the work side by side: eliminate the step, deterministic
automation (API or rules), an AI agent, an AI agent with human approval, and
keeping it human-only as the zero baseline. Each alternative takes its own
assumptions (minutes saved per eligible case, eligible share, recurring and
one-time cost); the approval alternative also subtracts human review minutes
per case, so review time larger than the saving shows a loss. Cases per month,
labor cost and currency come from the scenario above.

The result orders alternatives by modeled net value only. It records which
alternatives act without per-case approval and which still need confirmed
business rules, and it carries `recommendation: null`,
`approved_alternative: null` and `authorized_agent_actions: false`. Missing or
out-of-range assumptions are refused rather than defaulted, and changing any
assumption clears a stale comparison. When computed, the comparison is included
as `alternatives_comparison` in the exported scenario file.
