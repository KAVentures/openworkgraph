# Historical as-of next-activity validation (R19)

The next-activity workspace now has an independent historical landmark evaluation. Choose one to six UTC cutoffs, completion labels, observation horizon, history and minimum training support. Training uses only visible pre-cutoff prefixes whose last activity is a selected completion label. One prediction is attempted per case open at the cutoff. The first recorded next timestamp at or after the cutoff, within the horizon, provides the label; no subsequent event and tied different activity labels remain unresolved. Training with ambiguous ordering is excluded; ambiguous open prefixes abstain. No retrospective case filters are accepted.

Reports include complete open-population accounting, prediction coverage, resolved top-1/top-3 accuracy, whole-population hit-share bounds (abstentions count as non-hits), paired baseline comparisons on common predictions, and top-prediction calibration bins with unresolved bounds. Missing next events are never treated as a correct synthetic case-end prediction. Repeated cases across landmarks are disclosed, not pooled as independent measurements. This is reconstructed history, not a retained prospective prediction or independent proof of source completeness.

The dashboard offers landmark drill-down, exact source-bound paginated case evidence, JSON and CSV export. The existing prediction endpoints are unchanged. The new dashboard-only POST endpoints are /v1/event-logs/{log_id}/next-activity/landmarks and /v1/event-logs/{log_id}/next-activity/landmarks/evidence. Use format openworkgraph.next-activity-landmarks.v1, cutoffs, horizon_days, end_activities, optional history, min_support, minimum_training_cases and case_type. Evidence requires settings, expected_review_sha256, cutoff, status (all/resolved/unresolved/abstained), offset and limit. Fingerprints cover visible ordered event projection, exact settings and case notion. Changes refuse evidence pages.

Work limits: 300,000 visible events, 100,000 cases, 2,000 events per trace, 1.2M event-landmark workload, six cutoffs, one concurrent evaluation, and at most 100 cases per page. No truncation is called exact. Completion labels and cutoff rules are modeling choices; reopenings, backfilled history and missing source events may affect the reconstructed as-of population. No intervention, forecast or execution permission is inferred.

Synthetic case-end-only guesses have no possible hit against a recorded next activity, even for unresolved outcomes. The upper bounds exclude these guesses. HTTP regression coverage exercises dashboard-session authorization, stale review rejection, request size and unsupported retrospective cohort refusal.

When completion and non-completion activities share the final visible timestamp, membership is unknown independent of event ID order. The report shows exact uncertain membership counts, open-population size bounds, membership-sensitive prediction bounds and up to 100 examples. No prediction or training example is produced for those cases.
