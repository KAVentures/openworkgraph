# Interruption and resumption candidate triage

This local CLI adds a **review-only interruption classification** to ambiguous links generated by the production reconstruction queue. It does not infer a case from temporal proximity, change canonical membership, access a provider, or assert that an interruption is a true task boundary.

```bash
python -m server.reconstruction_interruption_triage --events observations.json --consent-local-review --pause-seconds 120
```

Input is a bounded local JSON array of ordinary OWG observation objects, subject to the existing queue's scope and evidence checks. Output includes the queue's evidence SHA-256, relation type, elapsed observed time, `short` / `paused` / `extended` category, and a human-review status. Competing candidates are explicitly marked `abstain_competing`; conflicting record identities, missing/cross-scope claims and tainted evidence are excluded. Duplicated event IDs with conflicting timestamps, missing timezone-aware timestamps, truncated queues and gaps exceeding 30 days are withheld. No raw titles, URLs, clipboard content or text are emitted.

**Acceptance boundary:** this is a useful diagnostic to prioritize interrupted work review, not autonomous case segmentation, a semantic scorer, calibrated probability or evidence that F1 improved. The production queue must first supply a non-time-only candidate. Verify against the frozen family holdout and consenting real sessions before adjusting linking policy. No acceptance of an individual proposal authorizes an agent or business write.

Run `python -m pytest tests/test_reconstruction_interruption_triage.py`; the full six-workflow CI and real-data acceptance remain separate gates.
