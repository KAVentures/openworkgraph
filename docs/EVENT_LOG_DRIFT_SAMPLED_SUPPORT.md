# Concept-drift minimum support uses sampled cases (#326 H4)

Concept drift constructs deterministic per-window `dcase` samples capped at `SAMPLE_PER_WINDOW` (currently 600). The directly-follows profiles, permutation null and resulting change-point tests use **only these sampled cases**. The full eligible case population is still reported as `windows[].cases`; `windows[].sampled_cases` and `windows[].sampling_truncated` disclose the actual analysis denominator.

A boundary is tested only when **both adjacent windows have at least `min_cases` sampled cases**. This corrects an earlier mismatch: a full window with 601 eligible cases but only 600 sampled cases could satisfy `min_cases=601`, even though the test used fewer than the requested minimum. Now it is conservatively skipped and counted in `boundaries_skipped_small_windows`. At `min_cases=600`, two windows each with 600 sampled cases remain eligible. `min_cases` validation (10–10,000) and the default of 30 are unchanged; choosing a value greater than the 600-case sampling cap necessarily suppresses all boundaries rather than implying support the test does not have.

This change does not alter case selection, sample hashes, path identities, statistical thresholds, p-value calculations, source events, API routes or existing response keys. The regression uses two synthetic 21-case monthly windows with a temporary 20-case cap to verify the exact threshold, the skipped-boundary count and the absence of false change points. It is **not** real-provider/customer acceptance, proof of representativeness, or evidence of causation. Consent, tenant isolation, authorization, retention, and action-approval behavior remain unchanged.
