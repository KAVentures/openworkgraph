# Resume the evidence-to-implementation journey

This is an additive, local-dashboard **guided navigation** feature for [#370 R5/M0](https://github.com/KAVentures/openworkgraph/issues/370), [#326](https://github.com/KAVentures/openworkgraph/issues/326) and [#264 Stages 5–7](https://github.com/KAVentures/openworkgraph/issues/264). It connects existing reviewed-process, opportunity, project-export and imported-report screens; it does not introduce a second workflow store, a new approval, or any execution capability.

## Analyst journey

1. Explicitly inspect an observed workflow or a selected retained log and save a process **after separate human review** in the existing process catalog. The observed path alone is not verified policy. Create an opportunity from the **saved immutable revision**, not unsaved editor changes.
2. In **Automation pipeline**, open the linked idea and choose **View evidence journey**. This makes one session-authenticated, read-only request to the existing `/v1/automation-pipeline/{idea_id}/journey` endpoint. Dataset/cohort origin checks, exact process revision and digest, idea state, exported project specification and archive digests, reported specifications and source-check export hashes are shown with explicit unknown/stale/unavailable labels.
3. Use **Resume this evidence-to-implementation journey** to request the **exact linked saved process revision**, not the latest process. If a newer revision exists, the historical basis remains marked changed; if the saved reference is unavailable or mismatched, the reopen action is disabled. Existing unsaved catalog edits still trigger their ordinary discard confirmation, which can be declined. Reopening does not restore approval.
4. **Continue at idea assessment or decision** scrolls to and focuses the existing assessment/decision control. An idea needs its existing human review and approval before the existing agent-project export can be used. For an approved idea without a project, **Continue at agent project export** focuses the existing export control; it never clicks it or creates a project.
5. After an explicitly requested export, select the exact recorded project in the journey. **Review reports for this exact project** opens the existing imported-report link review with that project selected. **Prepare source check for this exact project** opens the existing source-check form with that project selected, but **does not** supply a record reference, check its consent box, contact a provider, download a receipt or execute a business action. Source-check reads require the existing separate explicit confirmation and source permissions.
6. After closing/restarting the dashboard, reopen the idea and click **View evidence journey** again. The stages are reconstructed from stored server-side references, not browser session state. Changed or deleted source data, changed process revisions, historical idea/project revisions and missing reported specifications remain visible. The UI does not substitute a newer process or project.


## Portfolio human handoff-review inbox (explicit local read)

Open **Automation pipeline → Human handoff review inbox** and click **Review handoff gaps across opportunities**. This is a deliberate on-demand, authenticated read of the existing evidence journeys for **up to 12** approved or implemented opportunities **per page** in the currently loaded state filter. It is not a background scan, a company-wide audit or an agent run. At most three local journey reads are concurrent; the most recently updated eligible ideas appear first.

When there are more than 12 eligible ideas, use **Next 12 opportunities** and **Previous 12 opportunities** (Tab then Enter/Space) to review the other pages. Each navigation is an **explicit new authenticated read** for that page; it clears the prior page's rows and download before fetching. The visible page label identifies the selected page, exact 1-based range and total eligible count. The two navigation buttons are disabled at the first/last page respectively. An in-flight old page response cannot restore its rows or download after navigation. Filter changes, list refreshes and edits reset to page 1 and invalidate the previous review; click again to recheck. No background reads of other pages occur.

For each opportunity, the inbox selects the newest recorded export of the **current idea revision**, falling back to the newest historical export if none is current. It shows exact-project human-review blockers and the count of seven dependency stages needing review. An idea without an export is shown as **No recorded project**, not as a ready handoff. Missing, stale, malformed or truncated journey evidence is **unavailable/incomplete**, never silently treated as clear. Each row has an accessible **Open exact project review** action (or **Open opportunity** if no exact export); the target is re-read and must still exist. No implicit project substitution is allowed.

**Download minimized portfolio handoff review JSON** exports **only the currently reviewed page** as a point-in-time `openworkgraph.portfolio-handoff-review.v1` record (64 KiB maximum) with bounded project identifiers, specification/archive hashes, blocker categories, stage counts and explicit coverage/omission fields. It includes `page_number`, `page_count`, `page_start_index`, `page_end_index`, and counts of unreviewed eligible ideas before/after the page. `omitted_count` counts **all other pages**, not just later pages. A page is never evidence that another page was reviewed. Separate downloads cannot be merged into an authoritative snapshot because opportunity state can change between reads. It does not include raw cases, record references, source receipts, credentials or free-text notes. `complete_coverage=true` means only that every eligible opportunity **in the currently loaded state** was checked and had usable local project review metadata. It never certifies source completeness, execution, causality, business outcomes, enterprise coverage or agent authorization. All consent and approval boundaries remain unchanged.

### Review multiple pages in one local human-review record

After explicitly checking the first page, the **Human handoff review inbox** displays a cumulative count of pages and opportunities checked. Navigate to the next page and explicitly review it to add that page to the current in-browser review set. **Download reviewed pages together** exports one bounded (64 KiB maximum) `openworkgraph.portfolio-handoff-multipage-review.v1` JSON with only the pages actually read, their 1-based ranges, individual read timestamps, minimized blocker/status rows, and exact reviewed/unreviewed page numbers. No other page is fetched automatically. Rechecking a page replaces only that page's previous review; missing/unavailable project evidence remains incomplete.

The cumulative record is **not** an atomic cross-page snapshot, source receipt or authorization. Each page may have been read at a different time, so even `complete_coverage=true` only means all currently loaded eligible pages were explicitly checked and their local project-review metadata was usable at those separate read times. A missing page or unavailable project forces incomplete coverage. Changing the loaded opportunity list, state filter, search, priority/sort selection or editing an idea clears all accumulated pages and disables the combined download; the reviewer must explicitly recheck. If the combined record exceeds 64 KiB, download the individual page records instead. It contains no raw cases, credentials, receipts, source records or free-text notes, and does not grant consent, approval or agent execution. The Chromium acceptance exercises 13 real approved backend opportunities, two keyboard-reviewed pages, partial and combined downloads, duplicate/stale-page refusal, filter invalidation, accessibility and no review writes. Native CI and consenting-customer acceptance remain separate.

### Filter and open outstanding checks across reviewed pages

After checking at least one page, use **Triage outstanding checks from reviewed pages → Outstanding review check**. Choose a reported blocker such as **No recorded project**, **Saved process not current**, **No imported run report** or **Execution and outcomes unverified**. The list groups matching opportunities from **only pages you explicitly reviewed**, without another provider read or background scan. It displays the number of matching opportunities, how many loaded opportunities remain unreviewed, and at most **24 matching rows** at once; any additional matches are counted as omitted rather than silently discarded. A blocker that is not present in checked pages is not offered as a filter, but may still exist on unchecked pages.

Use Tab and Enter/Space on **Open exact project and check** to fetch the selected opportunity and its exact pinned project through the authenticated local journey, then focus the matching outstanding blocker. If no project exists, **Open opportunity for review** opens that idea without inventing an export. This is navigation to a human-review requirement, not an automatic remediation: no blocker is cleared, and no approval, source grant, execution permission, provider call or business write is performed. The focused check is re-read from current local evidence, so a deleted or changed project must not be substituted. Search, sort, filter, list refresh or idea edits invalidate the cross-page triage with the accumulated review. Counts are local point-in-time review metadata, never a company-wide verified outcome or cross-page atomic snapshot.

The browser acceptance uses the actual authenticated multi-page opportunity journeys to exercise blocker filtering, keyboard navigation, exact-project focus when available, 24-row truncation, invalid/forged blocker refusal, list-change invalidation, accessibility and read-only operation. Synthetic helper assertions do not substitute for native Chromium or consenting-customer UX acceptance.

## Triage outstanding handoff blockers on the first journey view

Once an exact exported project is selected, **Handoff review** lists each currently outstanding requirement with a safe, context-specific next step. No prior review packet or import is required. Use Tab to select an available action and Enter/Space to open the existing control for **that exact project**:

- A changed but still available saved design opens only its pinned revision. An unavailable or missing revision disables that action rather than substituting a newer process.
- Missing human approval or a historical idea revision focuses the existing opportunity assessment/decision. A historical export remains historical; navigation cannot make it current.
- Missing, mismatched, or truncated imported reports open the report-link review with the exact selected project preselected. A truncated summary remains incomplete.
- The independently unverified execution/outcome blocker can open the existing separately consent-gated source-state check, with the project preselected and source consent **unchecked**. A source-state receipt is not independent proof of execution, causality, value, or agent permission.
- Missing, changed or truncated dataset/cohort origins provide explicit instructions to return to the originating workspace, recheck consent, retention and completeness, and create a new linked reviewed basis when necessary. The pipeline cannot repair or certify source completeness.

Clicking any action **never removes a blocker** or changes approval state. These are navigation controls, not remediation, evidence verification, provider reads, project exports, or execution. Source-check submission retains its own record-reference and explicit-consent requirements. Changing idea/project invalidates old controls; after reviewing, refresh the authenticated journey to see the current saved state.

## Explicit handoff review packet

After opening **View evidence journey** and choosing a recorded project, use **Download review packet for this exact project**. This is a local, user-initiated JSON download with format `openworkgraph.evidence-handoff-review.v1`. It binds the chosen project ID, specification/archive hashes, saved process revision/digest and current source-status check, idea revision/state, source snapshot checks, linked reported-specification statuses, and recorded source-check document hashes. Switching the selected project rebuilds the packet for that project. Reopening after restart fetches the stored references again; refreshing the journey discards the prior UI selection and packet controls.

Source-origin and reported-specification lists are capped at **64 entries each**, with explicit truncation flags and review blockers if more exist. Omitted entries must not be mistaken for complete coverage.

The packet includes an actionable **human-review blocker list**: missing or changed saved process, absent/changed dataset/cohort, unapproved idea, historical project, missing or mismatched reported specification, and always-unverified execution/causality/business outcomes. A matching reported specification does not remove the last blocker. A deleted source changes the blocker on the next explicit refresh; the downloaded copy is a point-in-time review snapshot, not a live authorization. The packet contains no raw event/case text, step labels, observed-record refs, credentials, provider receipt bodies or business outcome assertions. A recorded source-check hash does not mean the receipt's result was verified.

This is an **optional review artifact**, not an agent configuration, signed receipt, independent verification, approval, or execution token. Downloading never calls a provider, runs a model, links a report, saves an idea, authorizes tools or initiates a business write. A human must still use the existing separate review and authorized runtime controls.

## Recheck an earlier review packet against current local evidence

In the selected project's evidence journey, choose **Previously downloaded review packet (local JSON only)** and **Compare saved packet with current local evidence**. OWG reads the file **only in the browser** (64 KiB maximum), validates the v1 human-review-only schema and its non-executable flags, and performs a fresh session-authenticated `GET /v1/automation-pipeline/{idea_id}/journey`. It never uploads the packet or performs a provider read. The comparison refuses packets from another idea or project, malformed JSON, invalid hashes/revisions and oversized files.

A matching result means only that the recorded process/idea/project identities and SHA-256 hashes, source-snapshot statuses, imported report statuses, source-check export counters/hashes and review blockers agree with the **new local read**. Changed categories are named for review, without rendering arbitrary text from the file. Refreshing the journey or switching project invalidates the comparison UI; late responses cannot populate the new selection. This is **not** a cryptographic signature, an approval, a live source verification or proof of execution, agent causality or business outcome. Revocation/retention may make prior evidence unavailable, and a point-in-time match cannot establish original data completeness. Re-check immediately before any separately authorized action.

## Review changed areas after a fresh packet comparison

When an imported packet differs from the **fresh authenticated local journey**, the comparison now provides keyboard-operable **Review changed areas** actions. They open the existing exact saved-process revision, opportunity assessment, selected immutable project, that project's imported-report review, or that project's separately consent-gated source-check form as appropriate. Review the changed categories before proceeding. The actions navigate or focus existing controls; **none** approves a decision, re-exports a project, reads a provider or performs a business write.

A changed or unavailable process can be inspected only when its **linked exact revision** is available; the dashboard never substitutes the newest revision. A historical project's source-check action is disabled, with an explanation. Dataset/cohort drift has no automatic repair action: return to the original data workspace and verify source availability, opt-in and completeness. Changed human-review blockers can be inspected in the selected project's checklist, but they are not marked resolved. Project artifact changes focus the explicit project selector rather than silently switching projects.

The review actions appear **only after a valid explicit comparison**. Choosing another packet, changing the project, or refreshing the journey discards the prior actions and any pending response; wrong-project and invalid files never retain actionable links. A matching snapshot provides no new approval or verification. Even after navigating, source reads still require a fresh exact record reference and unchecked-by-default explicit consent.

## Local human-inspection worklist after a fresh comparison

A valid **Compare saved packet with current local evidence** operation now creates a **Human inspection worklist** for the exact selected idea and project. It includes each changed comparison category and each still-outstanding current review blocker, even when the snapshot matches. Use Tab and Space to mark an item **inspected locally**; this is a temporary UI note that does **not** resolve the blocker, approve the process or idea, verify the source or authorize an agent. Items start unchecked on every new comparison.

**Download human inspection worklist** explicitly exports `openworkgraph.handoff-human-inspection.v1` as local JSON. It records the exact idea/project IDs, saved and freshly read process revision/SHA-256, opportunity revision, saved/current project specification and archive SHA-256, fixed category/blocker identifiers, and whether each was inspected locally. It records the number still uninspected and explicit false flags for approval, source-read authorization, execution and business-outcome verification. It does **not** include raw cases, event or step labels, observed-record references, receipt bodies, credentials, user-entered notes or arbitrary text from the imported packet.

The worklist is an **unsigned, user-marked coordination artifact**, not an audit-grade signature or a verified review decision. It does not persist to OWG or become an agent input. Downloading it never calls a provider, writes an opportunity, changes consent, runs a model or triggers a business action. The saved/current hashes identify the compared artifacts, not the completeness or truth of source evidence; a later source change requires a new explicit comparison. Changing the file, project, idea or refreshing the journey clears the temporary inspection marks and disables old download controls.

### Resume an inspection after restarting the dashboard

1. Keep both files downloaded for the same review: the **original handoff review packet** and the **human inspection worklist**. Close or reopen the dashboard; inspection marks are not stored automatically or silently restored.
2. Open the same opportunity and **exact recorded project**, choose the original review packet, then explicitly click **Compare saved packet with current local evidence**. This performs the existing fresh authenticated local journey read. The new inspection list starts unchecked.
3. Under the worklist, choose **Previously downloaded human inspection worklist (local JSON only)** and click **Restore local inspection marks for this exact comparison** (keyboard Enter works). Only the previously checked *inspected locally* items return. The restored marks remain editable and can be downloaded again; all blockers, approvals, consent and outcome-verification gates remain unchanged.

Newly downloaded worklists include a SHA-256 fingerprint of the **complete saved/current comparison snapshots**, excluding only their download timestamps. This binds source/cohort status, reported specifications, outstanding blockers, process/idea/project revisions and hashes, not merely the selected project ID. Import refuses an older worklist without this fingerprint, an unrelated idea/project, any changed comparison evidence, changed item keys/counts, unexpected fields, invalid authorization flags, malformed JSON and files larger than 64 KiB. A changed source or report requires reinspection and a new download. The fingerprint is **not a signature** and a user can edit their own local file; imported marks must never be treated as independently verified review or policy authorization. No file is uploaded, and no server-side inspection or approval state is written.

## Resume review from one portable file

After explicitly comparing an earlier review packet and marking the changed areas or outstanding blockers you inspected, click **Download resumable review bundle (one file)**. This creates a local JSON file (`openworkgraph.handoff-human-review-bundle.v1`) containing the original saved review packet and the current inspection worklist, bound to the complete saved/current comparison by SHA-256. The bundle is limited to **64 KiB**, contains no raw cases, source record references, receipt bodies or credentials, and is neither signed nor independently verified.

**Recommended restart flow — resume directly from the pipeline:** Open the Evidence tab. At the top of **Automation pipeline**, choose your saved bundle in **Resume a previous human review**, then press **Resume exact review from saved bundle** (keyboard Enter works). You do **not** need to search for the idea, reopen its process manually, choose a project, or separately import the packet. OWG validates the local file (64 KiB maximum), fetches the exact idea and its saved-project journey through the existing authenticated local endpoints, selects only the matching project ID, performs the same fresh comparison and restores *only* inspection checkmarks whose complete comparison digest still matches. Inspect the resulting drift and restoration status before continuing. If the exact idea or project was deleted or is unavailable, OWG refuses to select a substitute. The file is never uploaded and no source/provider read, approval or agent action occurs.

**Alternative manual flow:** Reopen the same opportunity and exact project in **View evidence journey**, choose the bundle under **Previously downloaded review packet or resumable review bundle**, then click **Compare saved packet with current local evidence**. The original two-file packet + worklist workflow remains supported. The top-level resume control accepts a resumable bundle, not a standalone review packet.

If a source, imported report, process revision, project, blocker or coverage state has changed, the drift comparison remains visible but the bundle's old inspection marks are **not** restored. Reinspect the changed evidence and download a new bundle. A forged execution/consent flag, unrelated project, unexpected wrapper field or oversized file is refused. Import never uploads the file, grants source access, records approval, verifies business outcomes, contacts a provider or executes an agent. A fingerprint is only a change detector, not a signature, and inspection is never an authorization.

## Compare two recorded agent-project exports before handoff

When an opportunity has **at least two separately recorded project exports**, open **View evidence journey** and use **Compare two recorded project exports**. Explicitly choose the baseline and candidate project IDs and press **Compare recorded project exports** (keyboard Enter). The comparison is a read-only view of the authenticated, locally stored journey; it does not export another project, contact a source/provider or run an agent.

The side-by-side table identifies each exact project's idea revision and whether it is current, specification and ZIP SHA-256, status counts of its recorded reported specifications, recorded source-check export count and most recent source-check document SHA-256. Each row is marked changed or matching. Reported specification counts are **not** per-run attribution, and source-check document hashes are **not** verified receipt results. Neither matching hashes nor differing hashes establish execution, causality, business benefit or permission to execute.

After comparison, **Inspect baseline exact project** and **Inspect candidate exact project** are explicit keyboard-operable navigation controls. Each selects only that recorded project in the existing evidence journey, revealing its own immutable artifact details, outstanding blockers and separately consent-gated review actions. Navigation invalidates the old comparison, and changing either comparison selector or refreshing the journey requires a new explicit comparison. Nothing automatically approves an idea, restores old approval, grants source access or initiates an agent handoff.

Comparison refuses the same project on both sides, missing project IDs, invalid/incomplete artifact metadata, and a truncated project list. A journey with fewer than two recorded projects cannot compare. Refresh the journey after another export or any report/source-check change; the table is a point-in-time local record comparison, not a live provider read or independent customer acceptance.

## Review dependency coverage for one exact project

After **View evidence journey**, explicitly choose the recorded project to inspect. Click **Review evidence dependencies for this project** (keyboard Enter or Space). This opens a seven-stage read-only matrix: dataset/cohort origin, saved process revision, human opportunity decision, immutable agent project, imported reports, recorded source-check exports and independent outcomes. Each row shows its **recorded local status**, exact available digest/revision or bounded count, and which earlier incomplete stages affect downstream review. This is a *review dependency map*, **not** an authoritative cross-store lineage graph or proof that all source events were observed.

For example, a missing or changed dataset origin makes downstream handoff review incomplete even when the saved process digest, approved idea and project ZIP hash are unchanged. A historical project remains an immutable recorded artifact but is not current for a new handoff. A matching imported specification is labelled **customer reported only**, and a source-check export is labelled **export hash only**: neither verifies a run, causality, source truth or business outcome. The final independent-outcomes row is always **unverified**; this UI cannot authorize an agent.

Use **Download minimized dependency review JSON** to save the exact selected project's point-in-time snapshot (`openworkgraph.handoff-dependency-review.v1`). The bounded, read-only artifact includes fixed stage statuses, recorded process/idea/project revisions and SHA-256, sanitized dataset/cohort origin digests/statuses, stage dependency impact and explicit false flags for source-read/execution authorization and independent outcome verification. It excludes raw case IDs, observed-record references, receipt bodies, credentials, free-text notes and event/activity labels. Export is capped at 64 KiB. The file is neither signed nor a provider attestation.

Switching projects or refreshing the journey discards the old matrix and download action; the reviewer must reopen the view for the newly selected exact project. The action performs no provider call, source read, report link, approval, project export, agent run or business write. Source availability and revocation must be rechecked in the original consented workspace. The review is useful for planning human follow-up, **not** for claiming an independently verified complete lineage.

## Safety and limitations

- The guide adds **navigation only**. It never automatically saves a process, approves an opportunity, exports a project, links a report, reads a provider, grants tool permissions or executes an agent. Existing REST/MCP and dashboard controls retain their behavior.
- A process digest binds a **saved design revision**, not the truth of its underlying events or company rules. A project specification/archive hash is a recorded artifact identity, **not** evidence that it ran. Imported monitoring reports are customer-reported and may be missing, unbound, changed or unverifiable; source-check exports retain hashes, not their receipt bodies or independently verified outcomes.
- Dataset/cohort origins may be absent or no longer accessible. A missing origin must not be called current, complete or source-verified. No automatic approval is inherited from any upstream stage.
- Actions are scoped to the currently opened idea; a superseding idea selection invalidates pending journey responses and old navigation controls. Project-specific controls use the exact project ID selected in the journey, not an unrelated default.
- Source deletion, revocation and retention can make an old reference unavailable. A downloaded project or receipt is an independent copy and is not retroactively recalled by the dashboard.
