# Follow-up evidence reassessment

Refs #1572, #1630 and #370. A completed-unverified operational follow-up can be compared against a separate, later selected evidence sample. The system recomputes both conformance evaluations under one organization transaction while both sets of publication grants remain live. It does not independently establish that corrective action occurred or caused a changed outcome.

## Review workflow

1. Preserve an explicitly approved baseline request from the linked case review console using **Download reassessment baseline request (JSON)**. It includes exact publication pins, linkage assertions, rules and the conformance digest. Treat this file as sensitive: it contains pseudonymous case membership and activity labels/codes.
2. After human completion has been recorded, publish separate later request windows. Each must start at or after completion and the corresponding baseline window end, and end no later than the current Gateway clock. Original and subsequent publications must coexist; the current Gateway has one publication per job, so distinct jobs/profiles are required. No historical grant is reconstructed from a receipt.
3. Review the later linked cases; export the reviewed linkage request, then supply the later rule definitions using the exact original rule IDs, types, count bounds and selector roles for the packet's rules. Explicitly map every original publication job to one distinct subsequent job and each selected original linked case to one distinct later linked case. The providers and activity disclosure modes must match; labeled activities must match exactly. Coded activities may have different profile-scoped pseudonyms and require explicit operator correspondence, with consistent one-to-one selector mapping. Mapped groups must preserve source membership multiplicity and evidence-basis category. The assertion is not independent business-identity verification.
4. In the exception triage console open the completed packet and download the comparison template. Copy the request objects into baseline and subsequent, supply the jobs and cases mappings (before/after), include confirm_conformance_review in each request, and upload the JSON. Review and approve correspondence. The preview recomputes the original queue's exact conformance digest and the later evidence checks. Baseline selectors must have been observed in the original reviewed scope. Later exact, operator-mapped selectors may be absent from the sample; an absent forbidden activity can be satisfied in the sample, but is not proof of actual remediation.
5. Approve the exact comparison and sample-only limitation to record a receipt and download the report. The transaction verifies current revisions, grants, item dispositions and comparison digest again. Only two digests, receipt time and the explicit unverified flag are retained with the original packet, not later case IDs, rule labels, source rows or outcomes. Up to ten distinct comparison receipts per packet; repeated equivalent comparisons are refused. Keep the downloaded report privately if needed; grant expiry cannot recall a downloaded copy.

The four reported outcomes are satisfied, not satisfied, indeterminate, and not applicable in the later sample. No original exception or human completion state is altered. Source completeness, causal effect, case correspondence and corrective action remain unverified. No source requests, writes, automated execution or notifications are performed. The template is a reviewed JSON workflow, not an automatic case/selector matcher.

## API

Owner-only POST endpoints under /v1/admin/connector-events/{organization_id}/exception-queues/{queue_id}/followups/{packet_id}/reassessment-preview and /reassessment-record. Preview requires exact queue/packet revisions, full baseline and subsequent conformance request objects, explicit job/case correspondence and approval. Record additionally requires the preview digest and explicit record/sample-only approval.

## Validation

Regression fixtures use the real Gateway publication store with synthetic later snapshot fixtures, exact original conformance, distinct source mapping, absent coded activity, stale review, duplicate recording, completed-window guard and revocation. Both combined review HTML scripts passed V8 syntax and static ID checks. Full Python/database/browser execution and live provider acceptance remain outstanding.
