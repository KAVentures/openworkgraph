# Exact object lifecycle conformance evidence (R24)

The object process model check now offers a separate exact lifecycle population review. Choose one reviewed object type and inspect the registered population, including objects with no visible events. The replayed variants use exactly the existing model projection, ordering, selection and replay limits. Counts of fitting, deviating and unknown objects reconcile to the registered population. Unknown objects include no visible events, overlong paths, variant omissions and replay-budget omissions. The all-object fitting share is reported as lower/upper bounds, never an estimate based only on fitting replayed objects.

Browse all replayed variants with pagination, all matching object memberships, or objects by status. Inspect individual token diagnostics and timestamp/event-ID ordered evidence pages, with tied timestamps explicitly marked. Unknown objects can expose visible event history but do not receive an individual replay result that would contradict the reviewed population. Token diagnostics are per activity, not causal or event-level attribution.

POST /v1/event-logs/{log_id}/object-process-model/conformance/lifecycle-review with model, object_type and optional max_variants to get the summary. Subsequent requests include expected_review_sha256, view (variants, objects, object), optional status, variant_sha256, object_id, offset and limit. The projected event membership, registered object IDs and selected type model are fingerprinted under the workspace lock. Changed evidence refuses paging; rerun explicitly. Pages are bounded to 100 rows, complete review to 1M projected events and 500k registered objects. The digest is not a complete raw-source fingerprint. Local dashboard session authorization is required.

This is an extension of the existing projection-based replay, not a full binding-based object-centric Petri net. It does not evaluate policy, independently verify relationships or authorize execution. JSON coverage export contains the reviewed model. Independent browser/native CI and customer validation remain required.
