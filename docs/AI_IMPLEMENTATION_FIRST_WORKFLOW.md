# First-workflow quick start

The existing implementation portfolio now contains a small, state-driven guide
for starting a first evidence-backed implementation. It reflects the actual
selected source files, prepared packet, proposal, reviewed title, structural
review and confirmed creation receipt. It does not infer that a workflow is
understood, approved, deployed or successful. Existing controls remain
available independently of the guide.

1. Open the observed-work selector, import original evidence JSON, or restore
   an exact local discovery checkpoint. The selector offers last 1, 4 and 24
   hours and last 7 days, based on the time of the explicit click. These
   populate the time fields only, clearing old candidate selections. They do
   not start capture, query evidence or replace the current handoff sources.
   Query and explicitly select examples using the existing bounded controls.
2. Prepare the selected evidence locally; inspect the actual coverage gaps.
3. Download a single original AI authoring text file, or the compact equivalent
   if the existing lossless compaction preview provides one. The file contains
   the matching existing instructions and the exact evidence JSON, unmodified
   at the end of the file, with representation, original digest and UTF-8 byte
   count in its header. The separate evidence and instructions downloads also
   remain available. No extra raw source files or credentials are appended.
   This is not a new proposal or evidence schema. Inspect locally; share only
   with an authorized AI. Compact bytes do not establish token savings or
   quality equivalence. No upload or inference happens from a download.
4. Import the returned proposal JSON or use the existing optional local model,
   batch or compatibility pathway. Enter a reviewed title and details.
5. Review the exact proposal against the original evidence. Inspect semantic
   claims and permissions separately from citation membership. Decide whether
   to create an unassessed idea or prepare a shadow skill using the existing
   separate explicit actions. The guide never creates an idea, approves,
   executes or replaces a workflow.

Editing the inputs invalidates the relevant state as before; single-file
downloads are disabled until a packet is prepared again. The guide adds no
persistent storage and no network request of its own. It uses the existing
authenticated preparation and review controls. A saved idea receipt is shown
only after successful creation in this browser session; the portfolio is
still authoritative.

Validation: run `node --test tests/js/ai_implementation_first_workflow.test.mjs`
and the existing integrated automation pipeline browser regression. Isolated
guide tests and browser smoke use synthetic state and substituted actions;
full backend/browser integration and real enterprise onboarding remain
unverified until combined CI and acceptance.
