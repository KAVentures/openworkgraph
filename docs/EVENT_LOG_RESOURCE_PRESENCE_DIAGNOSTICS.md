# Current resource-presence diagnostics for saved event logs (#326 R6)

`events_without_resource` is a **counts-only** diagnostic of the supplied/retained events, not a workforce metric. A resource identifier is *missing* when it is empty or consists solely of Unicode whitespace as recognized by Python `str.strip()` for identifiers that pass the existing control-character validation. A nonblank identifier remains supplied even when it contains leading/trailing whitespace, and the diagnostic never exposes the identifier.

The shared streaming reader already applies this presence rule, and new bulk CSV imports normalize ASCII-space-only resources on storage (#466). Older stored logs or other import paths can still contain whitespace-only resource fields. Current whole-log and prefix-scoped diagnostics now count those as missing, including non-ASCII spaces (such as nonbreaking, em and ideographic spaces). The check uses a fixed character set matching the Unicode whitespace code points allowed by existing identifier validation; forbidden control characters remain forbidden. No event, object, link or source value is rewritten.

The REST/MCP/dashboard field name and report structure are unchanged. Stored historical import/append reports remain historical snapshots with their original counts and digests; only newly computed current diagnostics and newly generated reports use this corrected presence check. Source bytes, stored-content hashes, permission/consent rules, tenant boundaries, deletion/retention behavior and action approvals are unaffected. A missing resource means no usable identifier was supplied in the retained event, **not** that the source had no assigned worker or that an employee performed poorly.

A synthetic DuckDB regression checks ASCII and Unicode whitespace, exact preservation of padded nonblank identifiers, independent append-prefix counts, and absence of source strings in diagnostic output. It does not establish real-provider completeness, customer acceptance, or competitor parity.
