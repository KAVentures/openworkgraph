# Exact mapping feasibility in the follow-up workbench

Refs #1572, #1634. Compatible candidate pairs are not necessarily jointly feasible. The mapping workbench now checks whether all reviewed original sources can be assigned distinct later sources, and after the operator chooses all source correspondences, whether all reviewed original linked cases can be assigned distinct later groups with the same mapped source multiplicities and evidence-basis category.

The initial source guidance includes all edges belonging to at least one complete injection. The operator can explicitly check remaining feasibility after choosing some or all source/case pairs. When impossible, the server returns a Hall-deficient subset: a set of remaining original records whose distinct remaining candidate neighbors are fewer than the records. The interface reports the conflict rather than silently proposing an identity. When possible, it reports feasible remaining options and their counts. No candidate is automatically selected. Source feasibility alone does not guarantee case feasibility for every source mapping; cases are assessed after the source mapping is complete.

The algorithm uses bounded augmenting paths for maximum matching and alternating-path reachability to determine exactly which edges participate in at least one left-saturating injection. It handles up to 50 original records and 500 candidates, including fixed explicitly selected edges. It neither returns a hidden chosen matching nor infers business identity, semantic activity correspondence, actual remediation, causal effect or execution authorization.

The owner-only mapping-feasibility endpoint accepts the existing guidance request plus expected_guidance_sha256, fixed_sources and fixed_cases. It independently recomputes live guidance and refuses stale pins, invalid or duplicate fixed choices. This is a read-only planning assessment with existing counts-only audit events, not a stored decision or execution authorization. The subsequent reassessment endpoints still independently validate the exact mapping and evidence. The guided UI clears comparison and feasibility approvals when inputs change, ignores delayed responses after edits, and binds recording to the exact preview request and digest. Advanced JSON reassessment is unchanged.
