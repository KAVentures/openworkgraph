# Bound attempt receipt inspection (experimental, local only)

`POST /v1/open-work/declarations/human-outcomes/attempt-receipts` requires an active local `Authorization: OWG-Session <token>` dashboard session, an explicitly connected Stripe source, current reviewed declaration and retained historical evidence, an imported run, and a previously operator-confirmed run/case binding. The request body uses the same fields as the imported-run binding route, except `action`: `work_item_ref`, `expected_revision`, `expected_edit_token`, `confirm_historical_review: true`, `confirm_run_comparison: true`, `max_cases` (1–4), `deployment_id`, `run_id`.

Tenant/source scope and actor are derived locally from the authenticated connection and dashboard session. No tenant, actor, attempt or provider verdict can be supplied by the caller. The server revalidates the imported run, reviewed declaration, source and binding after the journal read; a revoked session is denied before response. Missing journals return an empty list without creating storage. Expired entries are filtered from the response according to the current retention policy. Responses carry `Cache-Control: no-store`.

This is an **inspection-only** route. It does not ingest receipts, call providers, approve agent actions, establish provider causality or establish customer outcomes. Legacy journal entries are marked `local_untrusted_journal` because the offline journal previously delegated authorization and provenance to callers. Do not treat these entries as independent verification without a trusted, authorized provider recheck. The production writer, grant/consent-bound provider correlation, revocation/retention cleanup and operator UX remain required before roadmap #247 is complete.
