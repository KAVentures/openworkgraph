# Signed macOS release acceptance — required before notarized public distribution

These checks require a Developer ID-signed .app and .pkg installed on a **fresh macOS user account**. CI's ad-hoc signing and unit tests do not establish macOS TCC attribution or notarization readiness.

1. **Signer / bundle:** run `codesign --verify --deep --strict --verbose=2 /Applications/OpenWorkGraph.app`, `spctl --assess --type execute --verbose=4 /Applications/OpenWorkGraph.app`, and validate the submitted/stapled package. Ensure Info.plist has permission descriptions and the bundled interpreter and native extensions are signed.
2. **First run / capture:** launch by double-clicking the app (not Terminal), using a new user account without pre-granted Terminal permissions. Select Permissions… in the menu. Request Accessibility, confirm the system TCC prompt, open Accessibility Settings and approve OpenWorkGraph. Request Input Monitoring separately, approve if desired, restart capture if instructed, and use Permissions… again to check. Switch across at least three ordinary apps; ensure front app and window titles (for apps exposing AXTitle) appear, and permission refusal does not produce fabricated titles. Observe that no Apple Events/Automation grant is requested.
3. **Sensitive capture / lifecycle:** visit a secure text field and excluded private app to ensure no contents enter local evidence. Quit OpenWorkGraph and confirm its server and collector processes terminate; relaunch to verify persistence. Hard-kill during outbox write and restart; ensure no confirmed events vanish. Start a separate unrelated listener on port 8787, then launch OWG: verify a clear collision dialog and **no** evidence is sent to that process.
4. **AI clients / uninstall:** connect Claude Code, Claude Desktop and Codex to OWG. Add unrelated hooks/servers to each client's settings. Quit OpenWorkGraph and choose **Uninstall OpenWorkGraph…** from its menu (or run the installed `uninstall.sh` with confirmation), verify the managed hooks, telemetry configuration and MCP entries disappear, unrelated client settings remain, and AI clients still start successfully. Check both `~/Applications` and `/Applications`; signed package installs may need a macOS administrator password. Verify local evidence is gone.
5. **Retention scale:** in a disposable user account, age some events 30 days inside a recording session that also has today's events. Configure seven-day retention and manually invoke cleanup; ensure expired rows, JSONL copies and pending outbox IDs disappear while today's rows remain. Check hourly cleanup without a restart. Benchmark a disposable 300,000-event history against prior 63-second cleanup and 15-second startup numbers; do not claim performance is fixed solely from 2,000-event tests.
6. **Browser sensor:** until Chrome Web Store distribution is approved, the browser extension remains an optional unpacked/Developer mode install. Explain its requested website permissions in the onboarding/store listing and verify optional installation is not required for native app focus tracking.

## Distribution limitations

- Deleting the .app directly from Finder cannot execute any uninstaller; macOS does not offer apps a general "on trash" lifecycle hook. Tell users to use the **Uninstall…** menu first. If they already deleted the app, provide the standalone cleanup script and explain how to remove stale OWG integrations.
- Signed Apple TCC permission behavior is application/child-executable sensitive. A successful unsigned/dev run does **not** replace a clean signed test.
- Native AppKit plus Accessibility are used for foreground capture, not Apple Events; adding a broad Apple Events entitlement would be unnecessary without another explicit feature that actually sends Apple Events.
- Publishing to the Chrome Web Store and implementing Sparkle require separate distribution credentials, review and release controls; no surprise auto-update or browser access grants have been added in this PR.
