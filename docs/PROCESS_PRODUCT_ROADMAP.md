# Process discovery to verified automation

OWG's target is one connected experience: task mining, process mining,
workflow mapping, handoff to existing agents, and independent outcome
verification. Existing evidence, record graphs, procedural memory, source
adapters and agent traces remain the foundation.

## Shared foundation and next acceptance scenario

The [versioned process catalog](PROCESS_CATALOG.md) now extends existing
owner-scoped workflow knowledge. Designs retain an observed baseline, explicit
activities/transitions, declared rules and proposed implementation types.
Saving creates immutable revisions with optimistic conflict checks. Exports,
structural comparisons and agent projects identify the exact reviewed version.
No second evidence collector or model database was introduced.

The [organization catalog](PROCESS_COLLABORATION.md) publishes only explicitly
reviewed designs into a separate namespace in that same store. Authenticated
authors, exact-revision independent reviews, ownership and collaborator changes
are committed with minimal audits on SQLite and PostgreSQL. A new revision
requires a new review. Organization design reviews grant no business execution
authority; local evidence remains separate.

The generated implementation now passes an actual SDK MCP transport test against
owned synthetic tools with conditional writes, independent source readback and
replay prevention. No real business system was modified.

The next acceptance scenario requires an authorized real workflow: map tools
and case identity for one reviewed process, run its generated planner in a
customer-controlled sandbox, validate normal/exception cases against confirmed
business rules, and verify resulting operations with independent source
receipts. Extend that same model with production feedback and reviewer-approved
updates. Structural tests and synthetic data cannot certify that lifecycle.

Retain exact declared case identifiers for source joins; temporal adjacency
alone cannot establish workflow identity. Keep observation consent, evidence
access and execution permissions separate. Prefer existing authorized APIs
and agent runtimes over historical click replay.

[Declared rule checks](PROCESS_RULE_CONDITIONS.md) compare explicit predicates
with authorized supplied facts without retaining values or granting policy or
execution approval. Generated agents pause until a reviewed source-fact
implementation exists for those predicates.

[Organization design readiness](PROCESS_DESIGN_READINESS.md) inventories exact
saved revisions and missing declarations without treating design completeness
as deployment or execution approval.

[Current-source rule checks](CURRENT_SOURCE_RULE_CHECKS.md) compare confirmed
conditions with fresh authenticated provider state while preserving unknown
facts and the distinction between current records, historical cases and
execution permissions.

[Runtime source-rule bindings](RUNTIME_SOURCE_RULE_BINDINGS.md) support explicitly
reviewed current-source invariants before mapped actions. General temporal branch
execution, historical case attributes and live customer acceptance remain open.

[Source-aware route planning](SOURCE_AWARE_PROCESS_PLANNING.md) lets explicitly
authorized rule-check results inform proposals; exact source invariants, current
review and freshness are checked independently of model output. Planning and
execution remain separate grants.

[Current-source shadow evaluation](CURRENT_SOURCE_SHADOW_EVALUATION.md) compares
small explicitly authorized batches against customer-reviewed routes and
clarifications, using per-case fresh invariant receipts and the existing report
review flow. Historical ground truth, representative coverage, production
outcomes and automatic process-model changes remain open.

[Company fleet status](FLEET_RECORDER_STATUS.md) uses existing authenticated
recorder heartbeats with identity/freshness checks. Evidence age remains a
separate signal; missing reports do not establish stopped recorders or unhealthy
connectors. The admin view provides no remote recording controls.

[Participant/team cohorts](PROCESS_PARTICIPANT_COHORTS.md) connect explicitly
selected log labels to whole-case maps and timelines. Native identifiers in
those columns are replaced before upload; a browser-only lookup helps users
identify aliases while their selected file is loaded. Labels are not verified
people, handoffs or membership, and are never joined across imports.

[Complete-cohort comparison](PROCESS_COHORT_COMPARISON.md) measures differences
between explicitly reviewed populations from one saved log, reports exact case
overlap and reopens each whole-case selection in the explorer. Employee effort,
causal improvement, statistical independence and business outcomes remain unverified.

[Observed transition inspection](OBSERVED_TRANSITION_INSPECTION.md) connects
selectable arrows to full-path variant support and complete retained cases
containing the exact adjacent pair, while preserving existing cohort filters.

[Reviewed shared-case imports](REVIEWED_SHARED_CASE_IMPORTS.md) combine two to
four authorized exports through explicitly selected literal case keys while
preserving unmatched cases, import-scoped key aliases and per-event source
provenance. Provider/account identity, business boundaries and source
completeness remain unverified; no timestamp-based or cross-import join occurs.

[Activity label support](PROCESS_ACTIVITY_LABEL_SUPPORT.md) connects node
inspection to every selected event, with separate full-log and exact-variant
populations, unknown labels and bounded support tables. Counts do not establish
employee effort, real identity, source authority or automatic responsibilities.

[Activity-label case inspection](PROCESS_ACTIVITY_LABEL_CASES.md) opens complete
histories supported by the selected label on the selected activity, with
explicit missing-data semantics and preserved cohort/variant scope. Labels
elsewhere in a case are never promoted into step attribution.

[Source cohorts](PROCESS_SOURCE_COHORTS.md) select complete cases by import-scoped
source aliases and compare their full histories with exact population overlap.
Source/account authority, completeness and causal performance remain unverified.

[Explicit parallel process models](PARALLEL_PROCESS_MODELS.md) preserve paired
fork/join regions through reviewed design, BPMN/PDD/JSON and bounded structural
alignment. Incomplete searches remain unknown. Linear agent projects cannot
execute these new designs and are explicitly unavailable for them.
